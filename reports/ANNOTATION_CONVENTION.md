## Reverse-Engineered Convention

Based on systematic comparison of gold vs non-gold mentions:

### The Rule

A sentence S is linked to component C if and only if:

1. **S mentions C** (by name, synonym, or clear reference)
2. **S describes C's architectural role, behavior, or interactions** —
   what C does in the system, what services it provides, what data it handles,
   how it communicates with other components.

A sentence is **NOT** linked even if it mentions C when:

- S describes C's **internal package structure** (sub-packages, directory layout)
- S **lists implementation classes** within C ('contains helpers/utilities/exceptions')
- S is a **package overview** header ('Package overview contains X.a, X.b, X.c')
- S is a **meta-comment** about C's implementation ('X.Y is not a Java package')
- S is a **cross-reference** ('Refer to the API for...')

### Abstraction Level Boundary

The boundary is between **architectural abstraction** and **implementation abstraction**:

- **Architectural**: 'The Storage component manages persistent data' → LINKED
- **Implementation**: 'storage.entity contains classes that represent persistable entities' → NOT LINKED

Both sentences are 'about' Storage, but at different abstraction levels.
The gold standard only traces at the architectural level.
