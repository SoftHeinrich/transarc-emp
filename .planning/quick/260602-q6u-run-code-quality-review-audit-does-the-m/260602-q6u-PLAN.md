# Quick Task 260602-q6u: Code Quality Review + Metrics Audit

## Objective

Perform a thorough code quality review and correctness audit of the metrics
implementations, focusing on:
1. Mathematical correctness of each metric (MCC, MAP, ACF1, NDG, HUS, EMR)
2. Correctness of metric integration in `metrics_api.py`
3. Code quality issues — bugs, edge-cases, type errors, logic flaws

## Task 1: Metrics Correctness Audit

**Files:**
- `src/lib/new_metrics_analysis.py` — core metric definitions (MCC, MAP, ACF1, NDG, HUS, EMR)
- `src/lib/metrics_api.py` — unified API integrating all metrics
- `src/bias/evaluation_critique.py` — `_compute_decision_f1`, `_compute_component_f1`, `_compute_weighted_f1`

**Action:**
Review each metric implementation for:

1. **MCC (`compute_mcc`)** — universe size = |all_sents| × |all_comps|.
   Check: Is `all_files` universe consistent between `new_metrics_analysis.py` and
   `metrics_api.py`? In `metrics_api.py:compute_sad_code_metrics`, `all_files`
   uses only SAM-CODE gold paths; `new_metrics_analysis.py` adds result-only files.
   If result has FP files outside gold, `tn` can go negative → corrupted MCC.

2. **MAP (`compute_map`)** — verify AP formula and denominator.
   Check: In `new_metrics_analysis.py` at the SAD-CODE MAP section, gold is passed as
   `gs_sad_code_flipped = {(c, s) for s, c in gs_sad_code}` but `compute_map` expects
   `gold_links: set of (component_id, sentence_str)` where it does
   `for comp, sent in gold_links`. Verify the format is consistent.

3. **ACF1 (`compute_acf1`)** — weight = 1/component_size.
   Check: Files in multiple components get minimum weight (largest component).
   Is this semantically correct? Should it use maximum weight (smallest component)?

4. **NDG (`compute_ndg`)** — documented as [0,1] but can return negative.
   Check: Should negative values be clamped to 0? Is the random baseline formula correct?
   The `n_components` arg to `compute_random_f1` is never used — is this a bug?

5. **HUS (`compute_hus`)** — coverage × purity harmonic mean.
   Check: In `metrics_api.py`, SAD-SAM uses `gold_flip`/`res_flip` (sentence-first),
   SAD-CODE uses `enrolled`/`res` directly (already sentence-first). Verify both are
   grouped by sentence correctly.

6. **Sentence F1** in `metrics_api.py:compute_sad_sam_metrics` (lines 136-152):
   A sentence is a "TP" iff its gold and predicted component sets share ≥1 component.
   Check: `res_S` only includes sentences with at least one TP. Gold set `gold_S` includes
   ALL gold sentences. Verify: false-positive-only sentences are correctly excluded from `res_S`.

7. **Component F1** in `metrics_api.py:compute_sad_sam_metrics` (lines 153-157):
   Maps component IDs to names. Check: does `.get(c, c)` fallback cause incorrect
   collapsing when two different IDs lack a name?

**Verify:** Read the relevant function code directly and trace through the logic.
Do NOT fix anything — document all findings in SUMMARY.md.

**Done:** Summary lists all issues found with severity (BUG/WARNING/INFO), file, line.
