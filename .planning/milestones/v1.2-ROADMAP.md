## Phase Details

### Phase 7: Suite & Universe Reconciliation
**Goal**: The component suite is a finalized, tested, stdlib tool whose micro and
macro share one component universe, with the relationship to the existing
`metrics_api` headline `component_f1` resolved (reconciled or documented with the
numeric delta).
**Depends on**: v1.1 (`metrics_api`, `evaluation_critique`, `rq2_trivial_baselines`).
**Requirements**: CMP-01, CMP-02, CMP-06
**Success Criteria**:
  1. `python3 src/bias/component_suite.py [--level --project]` emits per-project +
     average CSV for `sad-model` and `sad-code`, reusing `calc_metrics` only.
  2. micro and macro are computed on the same mapped-only universe; an equivalence
     oracle asserts suite-macro == `per_component_macro_f1`.
  3. The divergence from `metrics_api` headline `component_f1` (≈0.795 vs 0.714 for
     swattr/transarc) is reconciled in `metrics_api` OR documented as a deliberate
     definition with the delta recorded in a `reports/` artifact.
  4. Re-running the tool regenerates the committed CSVs deterministically.

**Plans** (3, planned 2026-06-21):
- [ ] 07-01-PLAN.md — Finalize the suite: shared-universe micro/macro, gold-only tail, regen committed CSVs, re-confirm artemis long-tail (CMP-01).
- [ ] 07-02-PLAN.md — Reconcile the headline: drop the {b} fallback so component_f1 is mapped-only, regen in-repo artifacts, supersede the rest, record the delta (CMP-02).
- [ ] 07-03-PLAN.md — Standalone equivalence-oracle + determinism check script (CMP-06).

### Phase 8: Multi-System Comparison & Fitness Validation
**Goal**: A defensible, hardened comparison establishes — with a fitness scorecard —
that tail coverage (`min_comp`/`pct_missed`) is the level-stable discriminator and
which columns are headline vs diagnostic, across swattr/transarc, s20linker, artemis.
**Depends on**: Phase 7 (finalized suite + universe).
**Requirements**: CMP-03, CMP-04
**Success Criteria**:
  1. The suite runs over all three systems at both levels into a `reports/` artifact
     with the cross-level narrative (graceful skip for absent external roots).
  2. A fitness scorecard scores candidate columns on separation (trivial-vs-real),
     validity (oracle ceiling), stability (cross-project), and degeneracy.
  3. The scorecard is hardened beyond random/top-3 (≥1 cleverer baseline; legacy
     systems where data exists), and its verdict (headline = macro + tail;
     diagnostic = micro/gap) is stated with the supporting numbers.
  4. The artemis long-tail-abandonment finding is reproduced and quantified.

### Phase 9: Paper Integration
**Goal**: A reader of `eval.tex` Ch2 sees the level-agnostic component suite, the
tail-coverage discriminator (artemis abandons the long tail), and the
universe-reconciliation correction, with generated tables.
**Depends on**: Phase 8 (validated comparison + numbers).
**Requirements**: CMP-05
**Success Criteria**:
  1. A new/extended Ch2 section presents the suite and the two-level finding, citing
     only retained scripts/reports.
  2. Tables are generated via `src/paper/generate_tables.py` into `writing/tables/`.
  3. `eval.tex` validates structurally (labels/refs resolve; tables regenerate).

## Notes / Risks

- **swattr ≡ transarc at doc-to-code** (SWATTR ⋈ ArCoTL) — reported as one column;
  the live contrast is heuristic (uniform) vs LLM (peaky-but-leaky). If a *distinct*
  external SWATTR doc-to-code result is wanted, its path is an open input (Phase 8).
- **External result roots** (`agent-linker/results/`, `sota/recovered-links/`) are
  outside the repo; the tool must warn+skip if absent (CMP-03).
- **Honesty risk**: do not oversell micro-vs-macro — the reconciled finding is that
  aggregation is second-order and *tail coverage* is the story. Keep the paper claim
  matched to the reconciled numbers.
