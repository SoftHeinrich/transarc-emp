# Requirements: TransArc-EMP v1.2 — Component-Centric Metric Suite

**Status:** Active (defined 2026-06-21) | **Pillar:** 2 (benchmark bias) with Pillar-1 evidence

## Milestone Goal

Turn the exploration finding — that the component-centric view of TLR quality
generalizes across **both** doc-to-model and doc-to-code, and that *tail coverage*
(not the micro/macro choice) is the first-order discriminator — into a reproducible
metric suite, a validated multi-system comparison, and a paper section. Along the
way, fix the latent component-universe inconsistency between the two legacy
per-component-F1 definitions.

## Background (from the 2026-06-21 explore session)

- Two per-component-F1 aggregations coexist (MICRO = pooled pairs / volume-weighted;
  MACRO = per-component mean / size-blind) and were thought to diverge sharply.
- Reconciling them onto **one mapped-only component universe** showed the micro/macro
  *aggregation* effect is **second-order** (gaps within ±0.07/proj, ±0.02 avg). Much
  of the earlier "enrollment-inflation gap" (bigbluebutton −0.31) was a **universe
  mismatch** artifact (`_compute_component_f1` keeps unmapped files as singleton
  components `{b}`; `per_component_macro_f1` drops them `()`).
- The robust, level-stable signal is **tail coverage** (`min_comp`, `pct_missed`):
  artemis (LLM SOTA) has the worst tail at both levels (min_comp 0.345 code / 0.279
  model; `=0` on bbb & jabref) despite competitive headline F1 — it nails popular
  components and abandons the long tail; heuristic SWATTR is more uniform.
- Foundation already delivered this session: `src/bias/component_suite.py`,
  `reports/COMPONENT_SUITE*.{md,csv}`, memory `component-suite-finding`.

## Requirements

### CMP-01 — Level-agnostic component suite tool *(foundation delivered; needs hardening)*
A stdlib tool computes the suite `{micro, macro, gap, min_comp, pct_missed,
gold_gini}` for any system at `sad-model` and `sad-code`, on collapsed
(sentence, component) pairs, **reusing `calc_metrics` only** (no new F1 math), and
emits per-project + average CSV. Honors the project's no-leakage / stdlib-only rules.

### CMP-02 — Reconciled component universe
`micro` and `macro` are computed on the **same** mapped-only universe so `gap`
reflects aggregation alone. The divergence from the paper's current headline
`component_f1` (which uses the `{b}` fallback in `metrics_api`/`_compute_component_f1`)
is either reconciled in `metrics_api` or explicitly documented as a deliberate
definition, with the numeric delta recorded.

### CMP-03 — Multi-system, two-level comparison *(foundation delivered; needs hardening)*
The suite is run over swattr/transarc, s20linker, and artemis at both levels and
written to a `reports/` artifact, including the cross-level narrative and the
swattr≡transarc (SWATTR ⋈ ArCoTL) note. Missing external result roots degrade
gracefully (warn + skip).

### CMP-04 — Metric fitness validation
A scorecard justifies which suite columns are **headline** vs **diagnostic** using
explicit fitness criteria (separation of trivial baselines from real systems,
validity/monotonicity vs an oracle ceiling, cross-project stability, degeneracy).
Hardened beyond the random/top-3 baselines (e.g. frequency-rank / per-component
prior baselines; include legacy systems where data exists).

### CMP-05 — Paper integration
The suite, the tail-coverage finding (artemis long-tail abandonment), and the
universe-reconciliation correction are written into `writing/eval.tex` (Ch2,
extending the converged-axis story), with tables generated via
`src/paper/generate_tables.py`; `eval.tex` validates structurally and tables
regenerate. Cites only retained scripts/reports.

### CMP-06 — Reproducibility & equivalence oracle
A check asserts suite-`macro` equals `per_component_macro_f1` on the reconciled
universe (equivalence oracle, mini-src/check.py style) and that
`python3 src/bias/component_suite.py` regenerates the committed CSVs deterministically.

## Out of Scope (this milestone)

- New TLR systems or re-running ARDoCo/agent-linker pipelines (consume existing result CSVs only).
- A single composite scalar that replaces macro/micro — the suite keeps them distinct (macro headline, micro anchor/gap term).
- sam-code task extension (still deferred from v1.1).
- Real `pdflatex` PDF build (deferred; structural validation only, per v1.0 SC4).
