## Overview

This milestone ships a reproducible metrics-reporting API, a motivation study showing
how a misleading headline F1 distorts BOTH evaluation tasks, a converged metric
framework giving them one coherent story, and a handoff-ready workspace. Work flows
in one direction: build the metrics API first (Phase 4), use its output as evidence
for the consequences study + converged framework (Phase 5), then document the whole
two-pillar repo so a new reader can reproduce everything (Phase 6).

## Phase Details

### Phase 4: Metrics API
**Goal**: A user can point a stdlib-only API at a TransArc-format results file (sad-sam or sad-code) and get the full metric set out as both CSV and a ready-to-paste LaTeX table.
**Depends on**: Phase 3 (Pillar 2 metric code in `src/bias` + `src/lib`)
**Requirements**: MTR-01, MTR-02, MTR-03, MTR-04, MTR-05
**Success Criteria**:
  1. Running the API on a TransArc-format **sad-sam** results file produces a computed metric set for all benchmark projects (MTR-01).
  2. Running the API on a TransArc-format **sad-code** results file applies gold-standard enrollment and produces a computed metric set for all benchmark projects (MTR-02).
  3. The emitted metric set includes the per-task granularity metrics plus the proposed alternative metrics, reusing `src/lib` + `src/bias` with no benchmark-derived word lists (MTR-03).
  4. The API writes a CSV (Excel-openable, stdlib `csv` only) with one row per project covering the run in a single sheet (MTR-04).
  5. The API writes a LaTeX table of the same metrics, paste-ready (MTR-05).
**Plans**: 1 plan
**Outcome**: ✓ Complete — `src/lib/metrics_api.py` (`--task {sad-sam,sad-code} [--project]`), reusing existing primitives with zero metric-math reimplementation. **Key correction:** SAD-SAM has no file/enrollment granularity (link/sentence/component only; the SAD-CODE `_compute_*` enrollment helpers are fenced out of the sad-sam path); unified column schema with N/A cells. Verified 7/7 must-haves with published-value parity (JabRef File 0.943 / Decision 0.394).

### Phase 5: Consequences Study & Converged Metrics
**Goal**: A motivation analysis shows, with numbers, how misleading F1 distorts BOTH SAD-SAM (pure F1) and SAD-CODE (file-level enrollment F1), and proposes a converged metric framework giving the two tasks one coherent evaluation story — written up as a Pillar 2 paper section.
**Depends on**: Phase 4 (the metrics API output is available as evidence for the study)
**Requirements**: STUDY-01, STUDY-02, STUDY-03, STUDY-04
**Success Criteria**:
  1. An analysis quantifies what the headline **SAD-SAM pure F1** hides/distorts, output to a `reports/` artifact (STUDY-01).
  2. An analysis quantifies the misleading consequences of **SAD-CODE file-level (enrollment) F1**, consolidating prior bias findings (JabRef File 0.943 → Decision 0.394 flip) as motivation evidence (STUDY-02).
  3. A **converged metric framework** is proposed applying one common evaluation story across both tasks (STUDY-03).
  4. The findings + proposal are written into the paper as a motivation section extending Ch2, citing only retained scripts/reports; `eval.tex` validates structurally and tables regenerate (STUDY-04).
**Plans**: 2 plans
**Outcome**: ✓ Complete — `src/bias/consequences_study.py` → `reports/CONSEQUENCES_STUDY.md`; `t_consequences`/`t_converged_framework` builders in `generate_tables.py` → `writing/tables/*.tex`; new Ch2 section `sec:eval:misleading-both` + converged-axis protocol extension in `eval.tex`. Converged framework = Decision + Component level as the common honest axis across both tasks (sad-sam decision=link, no inflation; sad-code decision=raw pre-enrollment). Verified 11/11 must-haves.

  2. Each pillar has run/reproduce instructions a reader can follow to regenerate that pillar's reports from scratch (DOC-02).

## Milestone Summary

### Key Decisions
- SAD-SAM metric framing corrected mid-discuss: no file level; link/sentence/component granularities (user-flagged). This became the backbone of the converged framework.
- Converged metric = Decision + Component axis common to both tasks (not a single composite), layered atop existing corrected metrics rather than replacing them.
- Stdlib-only preserved: CSV (not `.xlsx`), no requirements.txt; no benchmark-derived word lists.
- No local pdflatex — paper validated structurally (table regeneration + label/ref resolution), consistent with v1.0 SC4 reframing.
